
****************** Preamble

A user is given a solution to an ASP (Answer set programming) program.
They ask something about this solution (which we call "real model") in the form of a query,
which might already be true and they want to know why is there,
or the solution does not include something they expected and want to know
what would need to be changed to have it in a solution.

Our system takes care of finding the new solution (which we call "hypothetical model") that satisfies the query.
The result will be a graph in form of un-ordered facts that represents a contrastive explanation.
Your task is to interpret this graph and generate a natural language explanation for the user. To help understand the meaning of the predicates, you will also be provided with their meaning.

I will explain to you how to interpret the facts representing the graph by going trough several examples with some additional annotations to introduce new concepts using with comments (after %). You must do the same type of reasoning for the graph I provide you and output a JSON with a short intuitive natural language explanation.


****************** Examples

------ EXAMPLE 1: (Remove cause)

- Cause edges
- Query excluded
- Irrelevant disconnected nodes

```
asplain examples/james-bond/encoding.lp  --explanation-preference examples/james-bond/explanation-preference.lp 0  --query "-p"
```

Predicates:

p: James was poisoned
d: James drank the drink
h: James was on holiday
a: James was administered the antidote

Contrastive Graph:

node(d). % d is a node
node(h). % h is a node
node(p). % p is a node
attr(node,d,abduced,rm). % d had to be removed from the real model to satisfy the query in the hypothetical model (Must be mentioned in explanation)
attr(node,d,origin,real). % d is in the real model
attr(node,h,origin,hypothetical). % h is in the hypothetical model
attr(node,h,origin,real). % h is in the real model
attr(node,p,query,exclude). % the user wants p to not be in the hypothetical model
attr(node,p,origin,real). % p is in the real model
edge(d,p,0). % edge 0 connects from node d to node p
attr(edge,0,origin,real).  % edge 0 is in the real model
attr(edge,0,type,cause). % edge 0 is a cause, so d is a cause of p
attr(edge,0,rule_id,1). % (This is not relevant for you)
attr(edge,0,rule_str,"p :- d; not a."). % edge 0 comes from the ASP rule "p :- d; not a."
attr(edge,0,rule_vars,()). % The variables used in the rule for edge 0. (In this case no variables are needed)


Interpretation of the graph:

Starting on the abduced, we know that d was removed from the real model and it is not part of the hypothetical model,
so it must be mentioned in the start of the explanation.
This means that we have to remove the fact that James drank the drink.
Since there is a cause edge from d to p in the real model, it means that drinking the drink was causing the poisoning of James.
With this we reached the query of not having p (james not being poisoned).
Since h is in both the real and hypothetical and it is not connected to the rest, this did not change and it is irrelevant so should not be mentioned.

Expected output:

{
    "explanation": "If James hadn't drunk his drink, he would not have been poisoned."
}

- Cause in real that is not in hypothetical

```
asplain examples/james-bond/encoding.lp  --explanation-preference examples/james-bond/explanation-preference.lp 0  --query "-p"
```

Predicates:

p: James was poisoned
d: James drank the drink
h: James was on holiday
a: James was administered the antidote

Contrastive Graph:

node(d). % d is a node
node(h). % h is a node

attr(node,h,abduced,rm). % h had to be removed from the real model to satisfy the query in the hypothetical model (Must be mentioned in explanation)
attr(node,h,origin,real). % h is in the real model
attr(node,p,query,exclude). % the user wants p to not be in the hypothetical model
attr(node,p,origin,real). % p is in the real model
attr(node,a,origin,hypothetical). % a is in the hypothetical model
edge(d,p,0). % edge 0 connects from node d to node p
edge(a,p,1). % edge 1 connects from node a to node p
edge(h,a,2). % edge 2 connects from node h to node a
attr(edge,0,origin,real). % edge 0 is in the real model
attr(edge,0,type,cause).  % edge 0 is a cause, so d is a cause of p
attr(edge,0,rule_id,1). % Irrelevant

attr(edge,0,rule_vars,()). % The variables used in the rule for edge 0. (In this case no variables are needed)
attr(edge,1,type,inhibitor). % edge 1 is an inhibitor, so a inhibits p
attr(edge,1,rule_id,1). % Irrelevant
attr(edge,1,rule_str,"p :- d; not a."). % edge 1 comes from the ASP rule "p :- d; not a."
attr(edge,1,rule_vars,()). % The variables used in the rule for edge 1. (In this case no variables are needed)
attr(edge,2,type,inhibitor). % edge 2 is an inhibitor, so h inhibits a
attr(edge,2,rule_id,2). % Irrelevant
attr(edge,2,rule_str,"a :- not h."). % edge 2 comes from the ASP rule "a :- not h."
attr(edge,2,rule_vars,()). % The variables used in the rule for edge 2. (In this case no variables are needed)


Interpretation of the graph:

Starting on the abduced, we know that h was removed from the real model and it is not part of the hypothetical model,
so it must be mentioned in the start of the explanation.
This means that we have to remove the fact that James was on holiday.
From h there is an edge 2 that takes us to a.
This edge is an inhibitor, this means that h was preventing a in the real model and
since h is not in the hypothetical then a can be true.
There is an edge 1 from a to p which is also an inhibitor.
Because a is true in the hypothetical then the p can't be true in the hypothetical since it is inhibited by a.
This reaches the query of not having p.
The edge 0 is saying that d is a cause of p, but since it is only in the real model and p is not in the hypothetical model, d is no longer enough to make p true. In this case, it was inhibited by a. This can be mentioned in the explanation but is not as relevant as the inhibitor.

Expected output:

{
    "explanation": "If James hadn't been on holiday he would had gotten the antidote.
    So even if he had drank the drink he would not have been poisoned."
}

------ EXAMPLE 4:

- Alternative model
- Nothing abduced

```
asplain examples/cleaning/encoding.lp  --explanation-preference examples/cleaning/explanation-preference.lp 0  --log info --query "-dirty(3)" --model examples/cleaning/model.lp --prune
```

Predicates:

time(T): T is a time
tired(T): I was tired at time T
rain(T): It rain at time T
dirty(T): Floor is dirty at time T
do(clean,T): Floor is cleaned at time T


Contrastive graph:

node(dirty(3)).
node(dirty(2)).
node(rain(1)).
attr(node,dirty(3),query,exclude). % user wants dirty(3) to not be in the hypothetical model
attr(node,dirty(3),origin,real). % dirty(3) is in the real model
attr(node,dirty(2),origin,real). % dirty(2) is in the real model
attr(node,rain(1),origin,real). % rain(1) is in the real model
attr(edge,0,origin,real). % edge 0 is in the real model
attr(edge,0,type,cause). % edge 0 is a cause so dirty(2) is a cause for dirty(3)
attr(edge,0,rule_id,6). % irrelevant
attr(edge,0,rule_str,"dirty((T+1)) :- dirty(T); not do(clean,T); time((T+1)).").  % edge 0 comes from the ASP rule "dirty((T+1)) :- dirty(T); not do(clean,T); time((T+1))."
attr(edge,0,rule_vars,(2,)). % edge 0 replaces the variables in the rule with a 2, this would be "dirty((2+1)) :- dirty(2); not do(clean,2); time((2+1))"
attr(edge,1,origin,real). % edge 1 is in the real model
attr(edge,1,type,cause). % edge 1 is in the real model
attr(edge,1,rule_id,4). % irrelevant
attr(edge,1,rule_str,"dirty((T+1)) :- rain(T); time((T+1))."). % edge 0 comes from the ASP rule "dirty((T+1)) :- rain(T); time((T+1))."
attr(edge,1,rule_vars,(1,)).  % edge 0 replaces the variables in the rule with a 2, this would be "dirty((1+1)) :- rain(1); time((1+1))."
edge(dirty(2),dirty(3),0). % edge 0 connects dirty(2) to dirty(3)
edge(rain(1),dirty(2),1). % edge 0 connects rain(1) to dirty(2)


Interpretation of the graph:

We start by noticing that nothing was abduced.
This means that there is no need make changes to fulfil the query.
In this case, we see that there are nodes that are not in both models:
Nodes dirty(3), dirty(2) and rain(1) are not in the hypothetical but are in the real.
This means that the query can be satisfied in an alternative model, so there was another
solution to the current program where the query was true.
So you must just state the relevant differences and say that this was an alternative.
Since nothing is abduced, we work staring from the query.
dirty(3) was a consequence of dirty(2) in the real model,
but now dirty(2) is not true so dirty(2) is no longer a cause.
dirty(2) was a consequence of rain(1) in the real model but now rain(1) is not in the hypothetical model.
Since nothing had to be changed for rain(1) to be removed from the real model, we can just say that rain(1)
could just not have happened.


Expected output:

{
    "explanation": "Alternatively, it could have been that it did not rain in time 1, so the floor would not have been dirty in time 2 and therefore it would not have been dirty in time 3."
}

We work from there to the query which is to include stand(anna).
Starting from age(anna,95), the reciprocal_inhibitor Edge 3 points to stand(anna), the query of the user,
which means that age(anna,95) which was true in the real model, cannot be part of the same model than stand(anna).

That is, anna cannot stand because she is older than 90.
This is enough to give a good explanation.
Additionally, we see another reciprocal_inhibitor Edge 4 from sit(anna) to stand(anna),
which means that sit(anna) which was true in the real model, cannot be part of the same model than stand(anna).
In the constraint associated with Edge 3 (#false :- 1 < #count { sit(P): sit(P); stand(P): stand(P) }; person(P).") we can read that a person P must be either standing or sitting, but not both.
However, unlike age(anna,95) that had to be removed to make the query true, making sit(anna) false in the hypothetical was an alternative (wasn't removed by abdcution),
BUT ONLY in the case that age(anna,95) is removed.
That is, reciprocal_inhibitor coming from age(anna,95) should be used as the main reason in the explanation.
