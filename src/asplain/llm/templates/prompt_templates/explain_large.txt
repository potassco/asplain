Hey! I am creating a system to generate explanation graphs of why an atom is or isn't part of an ASP program, and what would have to be changed to make it so.
You're going to be by expert alai in explaining these contrastive graphs to people who don't know anything about ASP or contrastive explanations.

My system
---------

Input:
    - program: An ASP logic program that solves the users problem
    - model: A stable model (which is a set of true atoms)
    - query: The query states what the user wanted on the model. It can be atoms that the should be part of the model or atoms that should not be part of the model.
    - explanation preference: Decides which atoms from the input could potentially be removed or added and what is the prefered explanation for the user.

Output:
    - A contrastive explanation graph, this graph will have nodes and edges with different attributes.
        It represents the contrast between the explanation graph for the given model real and the explanation graph for the found model hypothetical that makes the query true.
        Therefor the nodes of the contrasted contrastive graph are all the union of the nodes of the two other graphs.
        This graph has three type of edges to destinguish a cause from an inhibitor and a reciprocal inhibitor.
        Additionally, the graph indicates which atoms had to be added or removed to get the hypothetical graph. This is defined with attribute abduced whose value can be rm for removed and add for added.
        This are the things that had to be changed. If nothing had to be changed it means that there was another model filling the needs stated in the query.


Contrastive graph definition
----------------------------

Below you will receive a contrastive explanation graph which is represented over `node`, `edge` and `attr` predicates. The predicates form
the graph you'll have to use for your explanation.

#node(A)
    Defines a node in the graph
    - A: the node identifier (atom)

#edge(N,N',ID)
    Defines an edge in the graph. They represent the causal relationships between nodes,
    as well as negative relationships (inhibitors).
    - N: the origin node
    - N': the destination node
    - ID: the identifier of the edge (Required for muli-edges)

#attr(T,N,A,V)
    Defines an attribute for a node or edge.

    - T: the type of the element (node or edge)
    - N: the node or edge identifier
    - A: the attribute name
    - V: the attribute value

    === "T=node"

        - A=origin: V = either real or hypothetical.
            Real means that the node is part of the real model, hypothetical means that the node is part of the hypothetical model. It might be part of both.
        - A=abduced: V = either rm or add
            rm means that the node had to be removed to get the hypothetical model, add means that the node had to be added to get the hypothetical model.
        - A=query: V = either include or exclude
            `include` means that the node must be part of the hypothetical model, `exclude` means that the node must not be part of the hypothetical model

    === "T=edge"

        - A=origin: V = either real or hypothetical
            Real means that the edge is part of the real model, hypothetical means that the edge is part of the hypothetical model. If the edge is not in either then it is because it is used in the contrastive graph to join both the real and hypothetical graphs.
        - A=type: V = either inhibitor, cause or reciprocal_inhibitor
            - inhibitor: means that the origin node prevents the destination node to be part of the model
            - cause: means that the origin node is a cause for the destination node to be part of the model
            - reciprocal_inhibitor: means that the origin node prevents the destination node to be be part of the model and vice versa.
                 If two nodes are linked by an edge of this type (attribute type of the edge is reciprocal_inhibitor) it will always be that the nodes belongs to one graph but not the other one.
                 The identifier for this nodes will be a tuple ((I1,I2),(C_Num,Vars)) where (C_Num,Vars) identifies a constraint of the program.
